# RideCodec.dll — контракт C ABI (v1 → v3)

Источник истины: `include/ride_codec/ride_codec.h`. Этот документ —
человекочитаемое описание правил и истории версий.

## Назначение

RideCodec.dll — нативная обёртка над reference-реализацией формата RIDE
(проект rideent). Хост (плагин Paint.NET или другое приложение) передаёт
BGRA-буфер и опции, получает RIDE-файл; наоборот — RIDE-файл и опции
декодирования, получает BGRA.

## Общие правила

1. **Память.** Все выходные буферы выделены malloc'ом внутри RideCodec.dll.
   Хост освобождает их только через `RideCodecFree()` — прямой free()
   из другого CRT не допускается.
2. **Пиксели.** BGRA: 4 байта на пиксель (B, G, R, A), top-down, без
   выравнивания строк. Альфа: кодирование — игнорируется (RIDE v1 без
   альфы), декодирование — всегда 255.
3. **Потокобезопасность.** Функции независимы; внутренние потоки
   управляются полем `threads` (0 = hardware concurrency).
4. **Версионирование.** Структуры опций начинаются с `struct_size`;
   кодек читает только поля, покрываемые переданным размером. Новые
   поля добавляются строго в конец структуры.
5. **Ошибки.** Функция возвращает 0 при успехе, иначе — код ошибки и
   заполняет `RideError` (код + UTF-8 сообщение). Коды:
   0 ok, 1 invalid argument, 2 malformed input, 3 image too large,
   4 out of memory, 5 internal error.

## Экспорты

| Функция | Назначение |
|---|---|
| `RideCodecVersion()` | версия `(major<<16 \| minor)` |
| `RideCodecEncode(bgra, w, h, opts, &out, &out_size, err)` | BGRA → полный RIDE-файл |
| `RideCodecDecode(data, size, &w, &h, opts, &out, err)` | RIDE-файл → BGRA-буфер |
| `RideCodecFree(ptr)` | освобождение буферов кодека |

## Опции кодирования: RideEncodeOptions

| Поле | Версия | Значения |
|---|---|---|
| `profile_choice` | v1 | 0 Auto (эталонный rideent), 1 RGB, 2 Indexed, 5 QOI |
| `entropy` | v1 | 0 Off, 1 Auto (≥2% выигрыш), 2 On — rANS-слой |
| `linear` | v1 | 1 = флаг kFlagLinear в заголовке RIDE |
| `block_pixels` | v1 | 0 = 262144 (пикселей на блок) |
| `block_rows` | v1 | 0 = определять по block_pixels |
| `try_both_parses` | v1 | 1 = оба COPY-парса (лучшее сжатие) |
| `threads` | v1 | 0 = hardware concurrency |
| `quantize_colors` | v2 | 0 = не квантовать; 2..256 — квантование до N цветов, когда уникальных больше N |
| `dither` | v2 | 1 = Floyd–Steinberg при фактическом квантовании |
| `bw_palette` | v3 | 1 = при quantize_colors == 2 жёсткая палитра чёрный/белый |

### Правила применения квантования

- Применяется для профилей **INDEXED и AUTO**; **RGB и QOI — никогда**
  (защищено в коде, независимо от переданных опций).
- AUTO: квантованный INDEXED-кандидат конкурирует с RGB «кто меньше».
  Внимание: при quantize_colors > 0 и фото-изображении Auto вернёт
  палитровый файл. Если нужно гарантированно RGB — передавайте
  profile_choice = RGB.
- INDEXED: если уникальных цветов ≤ quantize_colors — палитра точная
  (квантование не выполняется, дизеринг не применяется); иначе —
  Median Cut в Oklab + 3 итерации k-means (ΔE = квадрат расстояния
  в Oklab), затем маппинг пикселей, при dither = 1 — Floyd–Steinberg.
- Дизеринг увеличивает размер файла (шум ломает RUN-операции).

## Опции декодирования: RideDecodeOptions

| Поле | Значения |
|---|---|
| `threads` | 0 = hardware concurrency |
| `max_pixels` | 0 = 1<<30; декодер отказывается от больших изображений |

## История версий контракта

- **v1** — базовые поля (профиль, entropy, блоки, потоки).
- **v2** — `quantize_colors`, `dither` (квантование для INDEXED/AUTO).
- **v3** — `bw_palette` (жёсткая ч/б палитра при 2 цветах).

Добавление полей в конец структуры обратно совместимо: старый хост
передаёт короткий struct_size, кодек игнорирует остальные поля.
Изменение/удаление существующих полей или их порядка — нарушение
контракта, требует новой мажорной версии.

## Сборка

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Требуется rideent (RIDEENT_ROOT, по умолчанию C:/work/rideent) с
собранной `build/libride.a` — CMake соберёт её сам при отсутствии.
MSYS2 UCRT64; для распространяемой DLL — статическая линковка
`-static-libgcc -static-libstdc++`.

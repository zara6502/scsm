# ChipDeck — дизайн плеера и плагинного API (draft v1)

Черновик для обсуждения. Источник ABI-определений: `include/chipdeck_api.h`.

## 1. Архитектура

```
+--------------------------------------------------------------+
|                         ChipDeck host                        |
|  tray (клик = play/pause)   окно плеера (скин)   плейлист/БД |
|  WASAPI-вывод   кеш файлов   диалог настроек   HTTP-отмена   |
+------------------+-------------------------+-----------------+
                   |                         |
        CHP_ENGINE DLL                      CHP_LIBRARY DLL
   (GME, libsidplayfp, ayfly,           (ModArchive API, BotB JSON,
    ASAP, stSound, VGMPlay...)           ModLand mirror, local dir...)
```

Host владеет: выводом звука (WASAPI, один общий экземпляр), UI, плейлистом,
кешем, настройками. Плагины stateless по отношению к host: движок живёт,
пока открыт handle сессии; библиотека — пока есть connect.

Два типа плагинов независимы: плеер с одним движком и без библиотек
работает как локальный плеер (drag&drop).

## 2. Движок-декодер: `ChipEngine`

Модель данных: файл → сессия (`ChipHandle`) → подтюны (`GetTrackCount`) →
поток PCM через pull-вызовы `RenderFloat/RenderInt16`.

Ключевые решения:

- **Pull-модель рендера.** Host сам решает темп и размер буферов; плагин
  никогда не выделяет PCM-память и не создаёт аудиопотоков. Гонки за
  аллокатор исчезают, WASAPI-слот один.
- **Позиция = сквозной счётчик кадров.** `Select(track, rate)` сбрасывает
  состояние; `Seek` опциональна (не всякая эмуляция детерминированно
  перескочит — поэтому флаг `CHP_ENGINE_SEEK`).
- **Длительность может быть неизвестна** (`flags & HAS_DURATION == 0`):
  AY/RMT-музыка циклится по прерываниям, и честной длительности нет. Host
  запоминает фактическую длительность первого прослушивания в своей БД.
- **Конец трека** = `Render` вернул меньше кадров, чем попросили
  (движок дописал тишину в остаток). Loop/повторы — дело host.
- **Визуализации** — опциональные `GetVoiceLevels` (уровни голосов 0..1:
  3 голоса AY, 3 канала POKEY, голоса SID) и `GetSpectrum` (полосы 0..1).
  Это данные для скинов; движок объявляет их в capabilities.

Потоки: `Render/Seek/GetTrackInfo/Get*Vis` — только из потока вывода звука
или UI-потока host'а по одному в момент времени; `Open/Close/Select` —
из любого, но не одновременно с Render. Простейшая семантика «один
вызов в момент времени», host сериализует сам.

## 3. Провайдер библиотеки: `ChipLibrary`

Модель: `Connect(config) → Query(request, callback) → Fetch(entry) → буфер
плагина → host копирует → FreeBuffer`.

Ключевые решения:

- **Сеть внутри плагина.** Плагин сам делает HTTP (у ModArchive нужен
  API-ключ и XML, у BotB — JSON), host сети не знает. Для HTTP в плагинах
  достаточно WinHTTP (системный), внешних зависимостей не требуется.
- **Блокирующий `Query` с колбэком и флагом отмены.** Результаты отдаются
  по одному — UI наполняется живьём; `cancel` — указатель host'а на
  `volatile int`, проверяется плагином. Никакой очереди сообщений или
  таймеров на границе ABI.
- **Настройки через схему** (`ChipLibGetConfigSchema`): id, label,
  default, `secret` (маскировать как пароль). Host хранит значения и
  передаёт в `Connect`. Паттерн повторяет `EncodeOptions` из Ride Codec API.
- **`entry_id` — стабильный строковый ID записи** в рамках библиотеки:
  host кеширует скачанное по нему и делает повторный `Fetch` без нового
  `Query`.
- **Скачивание через буфер плагина** (а не URL) — плагин может совмещать
  скачивание и протокольную обвязку (аутентификация, gzip, XML→файл).
  Прогресс — колбэком, отмена — тем же флагом.

Коды ошибок: базовые 1–8 определены в заголовке (`CHP_ERR_*`), плагины
могут расширять с 16 — документируя свои.

## 4. Скины — декларативные пакеты

Скин = ZIP/папка: `skin.json` + PNG. Никакого исполняемого кода.

```json
{ "api": 1, "name": "Glass", "author": "...", "window": {"w": 320, "h": 200},
  "tray": { "idle": "tray_idle.png", "playing": "tray_play.png",
            "paused": "tray_pause.png", "error": "tray_error.png" },
  "elements": [
    { "type": "image",  "image": "bg.png", "rect": [0, 0, 320, 200] },
    { "type": "button", "action": "play_pause", "image": "btn.png",
      "frames": ["norm", "hover", "pressed", "active"], "x": 8, "y": 152 },
    { "type": "spectrum", "source": "engine", "bands": 32,
      "rect": [8, 8, 304, 96] },
    { "type": "voices", "source": "engine", "rect": [8, 110, 80, 16] },
    { "type": "text", "source": "title", "rect": [96, 110, 216, 18],
      "font": {"face": "Segoe UI", "size": 12, "color": "#FFFFFF"} },
    { "type": "progress", "rect": [8, 132, 304, 6] },
    { "type": "rating", "source": "rating", "rect": [8, 142, 100, 14] } ] }
```

- **Кнопки**: действия фиксированы (`play_pause`, `stop`, `next`, `prev`,
  `open`, `mute`, `show_window`, `quit`) — скин не может выполнять произвольные
  команды.
- **Источники данных** (`source`): `title`, `author`, `format`, `rating`,
  `position`, `duration`, `lib_name` — host-каналы; новые каналы не ломают
  старые скины.
- **Визуальные каналы**: `spectrum`/`voices` берутся из capabilities движка;
  если движок их не даёт, элемент рисуется пустым (не ошибкой).
- **Масштабирование окна**: v1 — фиксированный размер скина (DPI-aware),
  scale-фактор хоста применяется целиком. Резиновые якоря — v2.
- **Лоток**: 4 состояния иконки из набора скина; падение скина →
  встроенный дефолтный вид, плеер работает.

## 5. Звуковой тракт

WASAPI shared, float32, частота согласуется с движком при `Select`
(движок может дать любую: 44100/48000 — host решает: ресемплинг или запрос
движку другой частоты; большинство эмуляторов умеют любую). Пауза = host
перестаёт вызывать Render (или рендерит тишину), движки stateful, пауза
«бесплатна».

## 6. Решения для v1 (утверждены)

1. **Воспроизведение**: только «скачал целиком → играю». Стриминг с
   частичной готовностью — кандидат в v2; `CHP_ENTRY_STREAMABLE`
   остаётся зарезервированным флагом.
2. **Локальные файлы**: drag&drop и открытие — средствами host.
   Плагина «local folder» нет.
3. **Формат вывода движка**: host выбирает float32, если объявлен;
   int16 — fallback.
4. **Плейлист** — отдельное окно host (системный Win32-лист); скин
   рисует только основное окно плеера и иконки лотка.
5. **Имя и префикс**: проект `ChipDeck`, ABI-префикс `CHP`.

# Сборка DLL-кодека HEIC

[English version](BUILDING.md)

В этом документе описана сборка `ride_codec_heic.dll` — кодека-декодера для
Far Ride Viewer 2 — из чистой копии репозитория. Сам контракт кодека описан
в [справочнике Codec API](../docs/CODEC_API.ru.md).

## 1. Что требуется

- **MSYS2** с окружением **UCRT64** (<https://www.msys2.org>).
- Пакеты в шелле UCRT64:

  ```bash
  pacman -S mingw-w64-ucrt-x86_64-{cmake,ninja,gcc}
  ```

- `curl` и `tar` (есть в MSYS2 по умолчанию) — нужны скрипту зависимостей
  для однократной загрузки исходников с зафиксированными версиями.
- Доступ в интернет — только при первой сборке зависимостей.

Получаемая DLL 64-битная и подходит к 64-битному Far Manager. Для другой
архитектуры используйте соответствующее окружение MSYS2 (например,
CLANGARM64 для Windows on ARM) и пересоберите в нём также зависимости.

## 2. Структура проекта

```text
codec-heic/
|-- CMakeLists.txt       DLL-кодек + тестовый стенд
|-- build-deps.sh        загрузка и статическая сборка libde265 + libheif
|-- src/
|   |-- codec.cpp        экспорты Ride Codec ABI (v1 + необязательные v2)
|   `-- heic_decoder.cpp  Probe (бренды ftyp) и Decode (libheif)
|-- tests/harness.cpp    грузит собранную DLL и проверяет контракт ABI
`-- deps/                создаётся build-deps.sh (в репозиторий не входит)
    |-- src/             исходники зависимостей (зафиксированные версии)
    |-- build-*/         деревья сборки зависимостей
    `-- inst/            установленные заголовки и статические .a
```

Исходники зависимостей **не хранятся в репозитории**. Скрипт
`build-deps.sh` скачивает точные зафиксированные релизы, поэтому сборка
воспроизводима:

- libde265 v1.1.3 (<https://github.com/strukturag/libde265>)
- libheif v1.23.7 (<https://github.com/strukturag/libheif>)

Обе библиотеки линкуются статически: итоговая DLL зависит только от
`KERNEL32` и системной UCRT (есть в Windows 10+), наружу экспортируются
только функции `RideCodec*`.

## 3. Сборка

Все команды выполняются в шелле **UCRT64** (или добавьте
`C:\msys64\ucrt64\bin` в `PATH`):

```bash
cd codec-heic

# 1) Статические libde265 + libheif в deps/inst (несколько минут)
bash build-deps.sh

# 2) DLL-кодек + тестовый стенд
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Результат:

- `build/Codecs/ride_codec_heic.dll` — кодек (положить в каталог `Codecs`
  рядом с `FarRideViewer.dll`);
- `build/codec_test.exe` — тестовый стенд.

Если префикс зависимостей перенесён, укажите его явно:
`cmake -S . -B build -G Ninja -DHEIC_DEPS_PREFIX=/путь/к/deps/inst`.

## 4. Тесты

```bash
./build/codec_test.exe build/Codecs/ride_codec_heic.dll <файл.heic> [out.bmp]
```

Стенд загружает DLL так же, как host, и проверяет:

1. таблицу экспортов (7 декодерных присутствуют, кодерных нет);
2. `GetInfo` / `GetId` / `GetCapabilities` — правила версий и полей;
3. `Probe` — реальный файл, мусор, усечённые заголовки, отказ AVIF-брендов;
4. `Decode` — формат пикселей, stride, размер буфера, значения пикселей;
5. `DecodeEx` — структуру метаданных;
6. повторяющиеся циклы Decode/FreeImage и повторный free;
7. пути с ошибками — мусорный ввод, null, фальшивый HEIC-контейнер
   (без падения).

Код возврата — число неудачных проверок; `0` означает, что контракт
выполнен. С ключом `[out.bmp]` декодированное изображение пишется в
24-битный BMP для визуальной проверки. Образец HEIC лежит в `../docs/`.

## 5. Типичные проблемы

| Симптом | Причина и решение |
|---|---|
| `Не найден .../libheif.a` при конфигурации CMake | Зависимости ещё не собраны — выполните `bash build-deps.sh` |
| `undefined reference to __imp_heif_*` | Слинковано с динамическим libheif или не задан `LIBHEIF_STATIC_BUILD` — пересоберите зависимости скриптом, а кодек этим CMakeLists |
| `undefined reference to __imp_de265_*` | libheif собран без `LIBDE265_STATIC_BUILD` — `build-deps.sh` передаёт его через `CMAKE_CXX_FLAGS`; используйте скрипт |
| `LoadLibrary` падает в стенде или Far | Несовпадение разрядности (32/64) или отсутствие UCRT на старых Windows |
| Кодек не появился в Viewer 2 после замены DLL | Реестр кодеков кэшируется на сеанс Far — перезапустите Far Manager |

## 6. Замечания для распространителей

- libheif — LGPL-3.0 / MPL-2.0 (двойная лицензия), libde265 — LGPL-3.0.
  При распространении DLL со статической линковкой по условиям лицензий
  может потребоваться передать объектные файлы или предложить исходники;
  см. файлы `COPYING` обоих проектов.
- Зафиксированные версии обновляются правкой URL тегов в `build-deps.sh`;
  после обновления прогоняйте тестовый стенд.

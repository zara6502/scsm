# Загрузчик кодеков и реестр

Этот документ описывает поведение `CodecModule` и `CodecRegistry` в Far Ride Viewer 2. Публичный контракт ABI отдельно описан в [справочнике Codec API](CODEC_API.ru.md).

## Назначение

- `CodecModule` загружает одну DLL-кодек, находит её экспорты, проверяет объявления ABI и владеет дескриптором модуля.
- `CodecRegistry` хранит успешно загруженные модули, предотвращает повторную регистрацию, сканирует каталог кодеков и предоставляет функции поиска.
- Декодирование и кодирование выполняются вызывающим кодом через проверенные указатели на функции. Сам реестр не декодирует и не кодирует изображения.

## Последовательность загрузки

DLL принимается после следующих проверок:

1. Модуль загружается через `LoadLibraryW`.
2. Проверяются четыре обязательных экспорта ABI v1:
   `RideCodecGetInfo`, `RideCodecProbe`, `RideCodecDecode` и
   `RideCodecFreeImage`. При отсутствии любого из них DLL отклоняется.
3. Вызывается `RideCodecGetInfo`. Проверяются базовая версия API, строки
   имени и расширений с завершающим нулём, а также синтаксис списка расширений.
4. Ищется необязательный `RideCodecGetId`. Если он присутствует, проверяется
   стабильный ASCII ID. Иначе резервный ID строится из имени DLL без расширения.
5. Ищутся необязательные `RideCodecDecodeEx`,
   `RideCodecGetCapabilities`, `RideCodecEncode`,
   `RideCodecFreeEncodedData`, `RideCodecGetEncodeOptions` и
   `RideCodecEncodeEx`.
6. Если `RideCodecGetCapabilities` отсутствует, модуль регистрируется как
   legacy-кодек только для декодирования. При этом необязательные ID и
   `DecodeEx` всё ещё могут использоваться, а Encode отключается.
7. Если Capabilities присутствует, проверяются размер структуры и версия.
   Кодек должен объявить Decode и выход RGBA8.
8. Проверяются связи между флагами capabilities и доступными экспортами.
   Противоречивые объявления приводят к отказу загрузки.
9. Если присутствуют одновременно общая схема Encode и `EncodeEx`, схема
   запрашивается и полностью проверяется до включения универсального Encode.

## Проверка Encode

Загрузчик обрабатывает необязательные интерфейсы кодирования так:

- Если флаг `RIDE_CODEC_CAP_ENCODE` не установлен, все указатели Encode
  отключаются загрузчиком.
- Если Encode объявлен, кодек должен предоставить
  `RideCodecFreeEncodedData`, хотя бы одну функцию кодирования
  (`RideCodecEncode` или `RideCodecEncodeEx`) и поддержку входного RGBA8.
- `RideCodecGetEncodeOptions` и `RideCodecEncodeEx` должны присутствовать
  одновременно. Схема без соответствующего кодера или кодер без схемы
  отклоняются.
- Legacy-реализация `RideCodecEncode` без общей схемы может быть загружена
  как модуль с поддержкой кодирования, но не показывается в диалоге Save As
  или профилях `s1`–`s9`. Для этих элементов интерфейса Viewer 2 требует
  общую схему и `EncodeEx`.

Проверка универсальной схемы охватывает:

- Полный размер структуры и ожидаемую версию схемы.
- Количество параметров (не более 16) и все зарезервированные поля.
- Уникальные стабильные ID параметров с завершающим нулём.
- Непустые UTF-8 labels с завершающим нулём.
- Для CHOICE — от 1 до 16 вариантов, уникальные числовые значения и ID
  вариантов, а также default, совпадающий с одним из вариантов.
- Для INTEGER — диапазон, положительный шаг и default, выровненный по
  диапазону и шагу.
- Для BOOLEAN — default только 0 или 1.
- Нулевые значения зарезервированных флагов и полей параметров.

Перед вызовом кодера просмотрщик повторно проверяет выбранные или сохранённые
значения запроса. Если сохранённый профиль больше не соответствует схеме
кодека, он не передаётся в DLL; пользователю предлагается настроить профиль
заново.

## Capabilities и формат пикселей

Текущий host принимает выход Decode в формате top-down RGBA8. Он отклоняет
структуру capabilities без Decode и выхода RGBA8. Также отклоняются
противоречивые объявления, например ALPHA без RGBA.

Неизвестные биты capabilities и форматов пикселей текущий загрузчик
маскирует. Разработчик кодека должен объявлять только реально реализованные
возможности и не рассчитывать на сохранение неизвестных битов host.

## Идентификаторы и конфликты

Стабильный ID из `RideCodecGetId` используется профилями экспорта и
настройками кодеков. ID должны быть уникальны среди зарегистрированных
модулей. Второй кодек с уже занятым ID отклоняется.

Если `GetId` отсутствует, загрузчик формирует резервный ID из имени DLL.
Для обнаружения модуля этого достаточно, но для кодека, чьи настройки или
профили должны переживать переименование DLL, рекомендуется явный стабильный ID.

## Сканирование каталога

`CodecRegistry::load_directory()` просматривает один уровень указанного
каталога. Рассматриваются только обычные файлы с расширением `.dll`
без учёта регистра. Подкаталоги не обходятся.

Кандидаты сортируются до загрузки, поэтому порядок регистрации детерминирован.
Повторная регистрация того же нормализованного абсолютного пути возвращает
уже загруженный модуль. Ошибочная DLL не мешает обработке остальных кандидатов.

Отчёт сканирования содержит:

- `discovered` — количество DLL-кандидатов;
- `loaded` — количество успешно зарегистрированных модулей;
- `rejected` — пути DLL и причины отказа;
- `directory_error` — ошибку открытия или перечисления каталога.

Тестовые заглушки кодеков находятся в отдельном каталоге `TestCodecs`,
а не в рабочем каталоге `Codecs`.

## Разбор расширений и выбор кодека

Поле `RideCodecInfo.extensions` содержит список расширений через точку с
запятой, например `qoi;png`. Начальная точка необязательна. Пробелы по краям
элемента удаляются, регистр букв нормализуется к нижнему. Допустимы только
ASCII-буквы, цифры, дефис и подчёркивание. Пустые элементы и недопустимые
символы приводят к отказу загрузки DLL. Повторяющиеся расширения внутри
одного списка объединяются.

Реестр умеет искать кодек по расширению, но совпадение расширения — только
подсказка. Выбор по содержимому выполняет
`CodecRegistry::find_decoder_by_content(data, size, extension_hint)`:

1. Сразу отклоняет null-указатель и пустой вход.
2. Если передана подсказка расширения, сначала вызывает Probe у кодеков,
   объявивших это расширение.
3. Если никто не распознал данные, вызывает Probe у остальных кодеков.
4. Внутри каждой группы сохраняет порядок регистрации и выбирает первый
   кодек с успешным Probe.

Совпадающее расширение никогда не заменяет неуспешный Probe. До Decode
обязательно распознавание полного файла.

## Время жизни DLL

Реестр хранит `shared_ptr` для каждого загруженного `CodecModule`.
Вызывающий код, который использует указатель на функцию кодека или буфер,
выделенный этим кодеком, должен удерживать собственную ссылку на модуль до
завершения операции и освобождения буфера.

Вызов `CodecRegistry::clear()` удаляет владение реестра, но DLL не выгружается,
пока вызывающий код хранит `shared_ptr`. Выгрузка происходит в деструкторе
последнего `CodecModule`.

Это правило относится и к декодированным изображениям, и к закодированным
данным. Перед освобождением последней ссылки на модуль обязательно вызовите
соответствующую функцию `RideCodecFreeImage` или
`RideCodecFreeEncodedData`.

## Тесты

`ride_viewer_codec_loader_test` проверяет:

- загрузку QOI и обнаружение Decode вместе с универсальным Encode;
- регистрацию legacy-DLL без Capabilities;
- отказ DLL без обязательного экспорта;
- отказ некорректных объявлений capabilities;
- отказ противоречивых объявлений Encode и неполных пар схемы/кодера;
- отказ повторяющихся ID кодеков;
- разбор расширений, нормализацию, поиск и конфликты;
- выбор по содержимому с правильной, неправильной и отсутствующей подсказкой
  расширения;
- продолжение работы модуля после очистки реестра, пока вызывающий код
  удерживает `shared_ptr`.

# Интеграция файлов Viewer

## Поддерживаемые типы файлов

- `get_supported_image_formats(registry)` возвращает имена и расширения всех
  зарегистрированных Decode-кодеков в порядке регистрации.
- `get_supported_image_extensions(registry)` возвращает уникальные расширения.
- `build_open_file_dialog_filter(registry)` формирует MULTI_SZ для
  `OPENFILENAMEW::lpstrFilter`: общий фильтр изображений, отдельный фильтр
  каждого кодека и `All files`.

Фильтр строится по фактически загруженным DLL. Он не фиксирует список форматов
в коде приложения и автоматически учитывает новые плагины.

## Документ изображения

`open_image_document(registry, path, error)` открывает файл через общий
декодер и возвращает `ImageDocument`. Документ хранит исходный путь и
декодированное изображение, а также предоставляет имя файла, имя кодека,
ширину и высоту. Сам пиксельный буфер доступен через `decoded_image()`.

`ImageDocument` владеет `DecodedImage`, который удерживает DLL до освобождения
буфера. Документ можно передавать будущему UI как единый объект.

## Границы этапа

Здесь реализован файловый слой и подготовлены данные для UI. Сам вызов
Windows File Open Dialog, навигация по каталогам, список недавних файлов,
предпросмотр и отрисовка остаются задачами UI-этапа.
